# 视觉设计（界面、海报、网页、App）

| 症状 | 方法论 | 一句话解释 | 写进提示词的具体指令 |
|---|---|---|---|
| 看不出重点，眼睛不知道先看哪 | 视觉层级（Visual Hierarchy） | 用大小、粗细、颜色、位置排出"先看什么、后看什么" | 只设 1 个视觉焦点；标题、正文、辅助信息至少 3 级字号，相邻级别差 1.25 倍以上；次要信息降低对比度 |
| 文字信息多的页面，重点被埋 | F 型阅读模式（F-Pattern，Nielsen Norman Group） | 人扫文字页时视线走 F 形：先横扫顶部，再顺着左边往下扫 | 最重要的信息放顶部横条和左侧竖列；每行、每段开头放关键词；不要把关键信息放右下角 |
| 图多字少的页面（落地页、海报）视线乱 | Z 型阅读模式（Z-Pattern） | 内容少的页面，视线走 Z 形：左上→右上→左下→右下 | 左上放品牌或标题，右上放导航或辅助信息，右下放行动按钮 |
| 元素乱、没秩序、像随手摆的 | CRAP 四原则（Robin Williams《写给大家看的设计书》） | 对比、重复、对齐、亲密性四条基本功 | 所有元素对齐到同一网格；相关的靠近、无关的拉开；同类元素样式完全一致；重要和次要要对比明显，不能"差不多" |
| 分组看不清，不知道哪些是一伙的 | 格式塔原则（Gestalt） | 人会把靠近的、相似的、被框在一起的东西看成一组 | 组内间距明显小于组间间距（至少 1:2）；同组用相同颜色或形状；需要时用卡片或背景色框起来 |
| 信息太多、太挤 | 渐进式披露（Progressive Disclosure） | 首屏只放最常用的，其余收进第二层 | 首屏只保留 80% 用户最常用的 3–5 项；其余放进"更多"、折叠面板或详情页 |
| 显得廉价、不精致 | 8 点网格 + 字号比例（8pt Grid / Modular Scale） | 间距和字号都按固定倍数来，整体就会显得整齐 | 所有间距用 8 的倍数（8/16/24/32/48）；字号按固定比例（如 1.25 倍）递增；留白加大；全局最多 2 种字体 |
| 颜色乱、太花 | 60-30-10 配色法则 | 主色占 60%，辅助色 30%，强调色 10% | 定一个主色、一个辅助色、一个强调色，强调色只用于最重要的按钮和提示；其余用中性灰 |
| 按钮难点、操作费劲 | 菲茨定律（Fitts's Law） | 目标越大、离手越近，越容易点中 | 主要按钮加大点击区域（移动端不小于 44×44pt）；常用操作放在拇指容易够到的位置 |
| 选项太多，用户犹豫 | 希克定律（Hick's Law） | 选项越多，做决定越慢 | 每屏主要选项不超过 5–7 个；给出推荐默认项；把选项分组 |
| 用户不知道怎么用、容易出错 | 尼尔森十大可用性原则（Nielsen's 10 Usability Heuristics） | 评估界面好不好用的十条经典标准 | 按十大原则逐条检查：状态可见、贴近现实用语、可撤销、一致性、防错、少记忆、提供帮助等 |
| 不同页面风格不统一 | 原子设计 / 设计系统（Atomic Design） | 先定好颜色、字号、按钮等最小部件，再组合成页面 | 先输出一份设计规范（颜色、字号、间距、圆角、按钮样式），所有页面只用这份规范里的值 |
| 苹果风、高级感做不出来 | 苹果人机界面指南（Apple Human Interface Guidelines） | 苹果官方设计规范，讲究清晰、克制、层次 | 遵循 Apple HIG：系统字体、大量留白、半透明材质分层、克制用色、动效跟手 |
