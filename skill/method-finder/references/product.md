# 产品方案、需求、PRD、功能优先级

| 症状 | 方法论 | 一句话解释 | 写进提示词的具体指令 |
|---|---|---|---|
| 需求模糊，不知道用户到底要什么 | 待完成的任务（Jobs to Be Done，JTBD） | 用户不是要产品，而是要完成某件事 | 用"当……时，我想要……，以便……"描述每个核心需求；先写任务再写功能 |
| 功能堆砌、什么都想做 | KANO 模型 | 把功能分成必备型、期望型、魅力型等，区别对待 | 把功能分为 必备 / 期望 / 魅力 三类；MVP 只做必备和最关键的期望型 |
| 优先级排不出来 | RICE 评分（触达、影响、信心、成本） | 用四个维度给需求打分排序 | 每个需求估算 触达人数×影响×信心÷成本，按分数排序并说明依据 |
| 范围太大做不完 | MoSCoW 法 + 最小可行产品（MVP） | 分出必须有、应该有、可以有、这次不做 | 每个功能标注 Must/Should/Could/Won't；第一版只做 Must |
| PRD 写不清，开发理解有偏差 | 用户故事 + 验收标准（Given-When-Then） | 用"在什么情况下，做了什么，应该看到什么"写清每个功能 | 每个功能写成用户故事，并附 Given-When-Then 格式的验收条件，包括异常情况 |
| 用户不用、不留存 | 福格行为模型（B=MAP，BJ Fogg） | 行为发生需要动机、能力和提示同时具备 | 逐一检查：用户动机够不够、操作是否足够简单、有没有在合适时机提醒 |
| 不知道用户在哪一步流失 | 用户旅程地图（User Journey Map） | 把用户从知道产品到长期使用的每一步画出来 | 列出每个阶段的用户行为、想法、情绪和痛点，标出最大的流失点 |
| 指标乱、不知道看什么 | 北极星指标 + AARRR 海盗指标 | 一个最能代表用户价值的核心指标，加上获客、激活、留存、变现、推荐五个环节 | 定义 1 个北极星指标；为 AARRR 每个环节各定 1 个指标 |
| 用户体验分析没有框架 | 用户体验五要素（Jesse James Garrett） | 战略、范围、结构、框架、表现五层 | 从 战略→范围→结构→框架→表现 逐层分析，问题先从下层（战略）找 |
