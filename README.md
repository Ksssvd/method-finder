# method-finder（方法论匹配器）

> 当你对 AI 做出来的结果不满意、总觉得不对劲但说不上哪里不好时，帮你先判断问题根源，再匹配最对症的专业方法论，直接重做出更好的结果，或给出最小改动的新提示词。

## 解决什么问题

用 AI 做东西时，常见的情况是：你觉得结果“不够好、没重点、不高级”，但自己不懂专业术语，只能说“改专业一点”“再优化一下”，结果 AI 越改越长、还是不对味。

其实 AI 本来就懂各种经典方法论（如金字塔原理、F 型阅读模式、迪士尼动画 12 原则等），只是你不点名它不会主动调用。`method-finder` 是一份给 AI 看的 Skill（操作说明书），帮你把“模糊的不满”翻译成具体症状和对症方法论。

## 它怎么做

1. **先判断根源，不乱套方法论**
   先把结果不好归类为 4 种原因之一：
   - **缺信息**：AI 不知道给谁看、为了什么或缺少素材 → 最多问 3 个问题补齐
   - **缺标准**：信息够了，但结果平庸、杂乱、没重点 → 进入第 2 步匹配方法论
   - **需求没想清**：自己也没想好想要什么 → 先给 2–3 个差异明显的方向来选
   - **工具做不到**：当前工具能力上限 → 直说做不到并给替代办法

2. **按“症状”查表，少而准**
   内置 12 张分领域对照表，只在需要时读取对应的一张，默认只选 1 个（最多 2 个）最对症的方法论：
   - 视觉设计（`design.md`）
   - 动画动效（`motion.md`）
   - 文章写作（`writing.md`）
   - PPT 与汇报（`presentation.md`）
   - 营销文案（`marketing.md`）
   - 视频与 AI 生图/生视频（`video.md`）
   - 产品方案（`product.md`）
   - 数据分析与调研（`analysis.md`）
   - 决策与规划（`decision.md`）
   - 写代码与技术方案（`code.md`）
   - 学习与讲解（`learning.md`）
   - 通用任务（`general.md`）

3. **以更好的结果为交付**
   - 文案、大纲、文章、方案等文字类任务：直接按方法论重做给你
   - 需要修改本地代码或耗时较长的任务：先说明方案，同意后再改
   - 在外部工具里执行的任务（如即梦生图/生视频）：保留原提示词，只做最小改动（新增不超过 5 条）

4. **新旧对比 + 教你下次怎么说**
   每次输出都列出“和原来相比改了什么”，并在结尾给一句带方法论名字的现成话术，方便你下次直接指挥 AI。

## 安装

### Claude Code / Codex 等本地 Agent

```bash
git clone https://github.com/Ksssvd/method-finder.git ~/method-finder
```

按你使用的工具创建软链接即可：

```bash
# Claude Code
mkdir -p ~/.claude/skills
ln -s ~/method-finder/skill/method-finder ~/.claude/skills/method-finder

# Codex
mkdir -p ~/.codex/skills
ln -s ~/method-finder/skill/method-finder ~/.codex/skills/method-finder
```

其他支持 `SKILL.md` 格式的 Agent，直接把 `skill/method-finder` 文件夹复制到对应的 skills 目录即可。

## 使用

装好后，直接把不满意的结果贴给 AI，说出类似下面的话即可触发：

- “帮我找方法论”
- “这个结果不满意 / 总觉得不对 / 说不上哪里不好”
- “做这个任务前有什么好方法？”（开工前避坑）

> 只是纠正明确小错误（如“把标题改成红色”）时不需要调用本 Skill。
