# 方法论匹配器

用户不满意 AI 的结果，常常不是 AI 做不到，而是提示词里没点出该用的方法。方法论的名字就是开关：说出"F 型阅读模式""迪士尼 12 原则"，AI 已有的相关知识就会被调用。本 skill 负责：**诊断问题 → 找到方法论的名字 → 翻译成具体指令 → 给出改写好的提示词**。

## 核心规则

1. **先诊断，再开方**。不按"任务类型"罗列方法论，而是按"哪里不满意"对症。同样是做 PPT，"看不出重点"和"太多字"要用的方法论不同。
2. **少而准**：最多推荐 3 个，第一个必须是最对症的。宁可只给 1 个。
3. **名字 + 具体指令，缺一不可**。只给名字用户不会用；只给指令下次又忘了。每个方法论都要落到这个任务上的具体要求，例如 F 型阅读模式 →"最重要的信息放在顶部横条和左侧竖列；每行开头放关键词"。
4. **只用真实、有公认名字、能搜到的方法论**。不确定名字或出处就不写，绝不编造。对照表里没有的，可以用自己的知识补，但同样要满足这一条。
5. **不是方法论能解决的问题要直说**：缺素材、事实错误、需求本身没想清楚、工具能力不够（比如模型画不出准确文字）时，指出真正原因，不硬套方法论。
6. **说人话**：用户可能完全不懂这个领域。方法论第一次出现时用一句大白话解释它是什么。

## 流程

### 第 1 步：弄清三件事

- **任务**：要做的是什么（给谁看、用在哪）。
- **当前结果**：对话里已经有结果就自己看；没有就请用户贴出来或描述。
- **不满意的地方**：用用户自己的话。

缺的信息在**一条消息里一次问完**。用户只说"感觉不对"时，不要追问抽象问题，而是自己看结果，列出 2–4 个可能的具体症状让用户选，例如："是 ① 看不出重点 ② 太挤 ③ 风格不统一 ④ 显得廉价？"

### 第 2 步：诊断

把模糊的不满翻译成**能指认的具体症状**（例如"不高级"→"字号层级少、留白不够、颜色超过 4 种"）。一个结果可能有多个症状，挑影响最大的 1–2 个处理。

同时判断是否属于规则 5 的情况。

### 第 3 步：查对照表

按任务领域打开对应文件，**只读需要的那一个**（跨领域的任务最多读两个）：

| 领域 | 文件 |
|---|---|
| 界面、海报、网页、App 视觉设计 | `references/design.md` |
| 动画、动效、转场、角色设计 | `references/motion.md` |
| 文章、报告、邮件、说明文字 | `references/writing.md` |
| PPT、汇报、演讲 | `references/presentation.md` |
| 营销文案、标题、卖点、品牌 | `references/marketing.md` |
| 视频、分镜、故事、AI 生图生视频 | `references/video.md` |
| 产品方案、需求、PRD、功能优先级 | `references/product.md` |
| 数据分析、调研、竞品分析、找原因 | `references/analysis.md` |
| 做决定、做规划、定目标 | `references/decision.md` |
| 写代码、修 bug、技术方案 | `references/code.md` |
| 学习、讲解、教别人 | `references/learning.md` |
| 任何任务通用（结果不稳定、一次做不好、偏题等） | `references/general.md` |

表里每行是：症状 → 方法论 → 一句话解释 → 写进提示词的具体指令。按症状找，不按名字找。

### 第 4 步：按固定格式输出

```
## 问题诊断
（一两句话：结果具体哪里不好，根源是什么）

## 推荐方法论
### 1. 方法论名字（英文名，如有）
- 是什么：一句大白话
- 为什么对症：对应上面哪个症状
- 用在你这个任务上：2–4 条具体要求

（第 2、3 个同样格式，可省略）

## 改写后的提示词
（完整、可以直接复制使用的提示词，用代码块包起来。
 要包含：原任务、点名的方法论、具体要求、验收标准。
 保留用户原提示词里有用的部分，不要丢掉用户的原始需求。）

## 下次可以直接这样说
（一句话的简短版本，例如："按 F 型阅读模式重新排版，重点放左上。"让用户记住方法论的名字。）
```

### 第 5 步：验证（可选）

如果当前对话本身就是执行任务的地方，问用户要不要直接按新提示词重做。重做后，把新旧结果并排对比，逐条说明方法论带来的具体变化。如果没有变好，承认并换一个方法论，不要硬说变好了。

## 用户在任务开始前就来问

跳过第 1 步的"当前结果"，改为预判这类任务最常见的 2–3 个失败点，每个配一个方法论，直接给一份"一开始就写对"的提示词。
